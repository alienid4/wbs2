# 專案 WBS 追蹤系統

單人用的本機 Web App。回答三個問題：**今天要做什麼**、**哪些沒做完會 delay**、**這一階段的文件交齊了沒**。
週五按一個鍵產出進度週報。

---

## 一、啟動

```
雙擊 start.bat
```

會自動開瀏覽器到 `http://127.0.0.1:8765/`。關掉那個黑色視窗就結束服務。

需求：Python 3.8 以上，安裝時勾選 *Add Python to PATH*。
**沒有任何第三方套件**，不需要 `pip install`，公司電腦裝不了套件也能跑。

---

## 二、移植（換電腦時）

```
帶走：app/  config.json  start.bat
可選：data/wbs.db     ← 帶了保留現有進度，不帶則重新建立
```

到新機器後，只改 `config.json` 裡的 `docs_root` 指向文件目錄，其餘不動。

**設計上刻意做到的事：**

| | |
|---|---|
| 資料庫存什麼 | 任務、狀態、進度、文件的**相對路徑** |
| 資料庫不存什麼 | 文件本體。App 從不開啟、複製或搬移你的文件 |
| 唯一與機器綁定的地方 | `config.json` 的 `docs_root` 一個欄位 |

所以移植時你只需要在意 source code —— 文件留在原地，換台機器指過去就好。

**每次啟動會自動備份**一份 `data/wbs.db` 到 `data/backups/`（留最近 14 份），誤刪或改壞了
直接從那裡複製回來即可，不用自己記得手動備份。改動 `app/` 底下的程式碼後，建議先跑
`py tests/smoke.py`（煙霧測試，跑在暫存 DB，不會動你的正式資料）確認排程引擎沒被改壞。

## 四、核心觀念：浮時（float）

系統判斷「延遲」的唯一依據，不是進度條，是**浮時**。

> **浮時 = 這項工作最多還能拖幾個工作日，而不影響全案完工日。**

| 標記 | 意義 | 你該怎麼做 |
|---|---|---|
| 🛑 | 已逾期 | 今天最優先，每拖一天下游全部順延 |
| 🔴 | 浮時 ≤ 0 | 今天不能拖，落後即全案延遲 |
| 🟡 | 浮時 1–2 天 | 還有一點調度空間，但沒有第二次 |
| ⚪ | 浮時 > 2 天 | 落後不致影響全案 |
| 🌀 | 前置關係形成循環 | 浮時算出來的數字不可信，先去「前置」欄檢查是不是互相指向對方 |
| ✅ | 已完成 | — |

浮時是從**相依關係**算出來的。WBS 表上的「前置」欄沒填，就等於告訴系統「這件事沒人在等」——
浮時會被高估，紅燈永遠不亮。**這欄是整套系統的命脈。**

相依關係語法：

| 寫法 | 意義 |
|---|---|
| `A3` | A3 做完，本項才能開始（FS，預設） |
| `A3:SS` | A3 開始，本項才能開始（同步併行） |
| `A3:FF` | A3 完成前，本項不能完成（收尾對齊） |
| `A3:FS+5` | A3 做完後再隔 5 個工作日 |

> 你原表的「Phase 2 正式上線」與「環境建置／整合測試」期間是重疊的，
> 所以預設設成 `A8:FF,A9:FF`。若實際上是做完才能上線，改成 `A8,A9`。

## 四之二、基準線（baseline）——回答主管「當初講幾號，現在為什麼晚了」

`planned_start`／`planned_end` 是你隨時在調整的**目前計畫**。沒有一個固定的「原本說好的日期」，
就沒辦法回答主管最常問的那句話，而且只要把日期往後拖，紅燈會自己熄掉——這是舊版本最大的洞。

**凍結基準線**（「專案 WBS」頁，或先在「設定」頁填好「目標完工日」）：
把當下的 `end_date` 定為對主管的承諾（`project.baseline_end`），每個任務的目前計畫日同步存一份快照
（`task.baseline_start/baseline_end`）。凍結後這個承諾日是**天花板**：任務排到承諾日之後，
浮時會算成負值、觸發 🔴 will_slip，而不是終點跟著任務一起往後漂、紅燈跟著熄掉。

**重新基準化**：真的要調整承諾（主管核准展延）才用，**必須填理由**，理由與版次留在
`baseline_revision` 表，週報會印「本案已重新基準化 N 次，最初承諾完工日：XXXX」。改一次
`end_date` 不會自動變成新承諾——凍結前 `end_date` 隨時可改，凍結後只有「重新基準化」能動承諾線。

**里程碑**：WBS 表新增列時把「層級」設 `M`（開始日＝結束日，零工期事件），適合放「決標」
「上線」「驗收」這種主管真正在追的日子。週報與 HTML 週報都會單獨列一節「里程碑」，
不會混在一般工作項目裡。

**實際完成日**：任務狀態改成「已完成」，`actual_finish` 自動蓋今天（今日頁「記錄」按鈕、
WBS 表格改狀態都會觸發），事後可以在「實際完成」欄手動修正。週報「本週完成」看的是
**實際完成日落在哪一週**，不是計畫區間——遲交的任務會在它真正結案的那週出現，並印出
「較原訂遲 N 個工作日」，不會結案後就從所有週報裡消失。

## 五、頁面結構

頂層分頁：**今日**（跨兩案彙總） → **每個專案各一個分頁**（P01、P02…有幾個專案就長出幾個）
→ **週報**（跨案交付物） → **設定**（環境參數）。今日/週報/設定是全案彙總或環境層級的東西，
維持獨立分頁；專案本身的操作全部收進它自己的分頁，不用選專案下拉。

**今日** — 開機第一眼看的。今天的工作依「不能拖／吃緊／有彈性」分組，
每列可以直接改進度（0/50/100）與狀態按「記錄」。**這是週報的唯一資料來源**，每天花 5 分鐘就好。
第一次使用、假日或基準線還沒設定時，這頁會出現「上手提醒」橫幅，點項目可直接跳去對應專案分頁。

**每個專案分頁**裡面再分三個子分頁，切換不用捲動找東西：

- **總覽** — 回報用的畫面，看這頁就夠。九階段路徑圖（綠打勾＝已完成、藍實心＝現在在這、
  灰空心＝還沒到）＋一句白話狀態句（「目前處於 S02 立案簽呈階段，本階段必繳文件還缺 3 份…
  較原訂承諾晚 5 個工作日」，全部從既有欄位算出來，不是編的文字）＋重要里程碑時間軸
  （日期＋編號圓點，每個里程碑配一張卡片，內容是它所屬階段的任務完成/未完成清單與缺件，
  自動帶）＋KPI 卡片。「現在階段」直接用「文件與階段」子分頁裡每個階段的狀態下拉算，不是
  新欄位——所以那個下拉要跟著實況維護，不維護，總覽這句話就不準。
- **WBS 表** — 任務表，日期欄是原生日期選擇器、其餘格子點了就能編輯，打錯格式或指到不存在的
  項次會被擋下並還原、不會悄悄把浮時算錯。最晚完成日、浮時、判定三欄自動算，不可編輯。
  預設只顯示 7 個常用欄位，按「進階欄位」展開其餘 9 個（承諾完成、浮時、備註…）。
  頂端有基準線狀態列（凍結／重新基準化）。新增工作項目時勾「設為里程碑」，這項就會以
  零工期事件的形式出現在總覽的里程碑時間軸——記得同時填上「階段」欄，卡片內容才有得抓。
  改「項次」編號時，其他任務「前置」欄裡引用它的地方會自動一起改，不會讓相依關係無聲斷掉。
- **文件與階段** — 9 個階段，每階段列出必繳與選繳文件、是否已在目錄裡找到。
  必繳未齊時把階段標記為「已完成」會被擋下（可強制通過，但會被記進週報）。
  每個應繳項目旁邊有「📤 上傳」按鈕——選檔案，系統自動照命名規則存進正確的階段資料夾
  （專案代號／階段序／文件代碼都自動帶，版次自動抓現有最大版次 +1），存完立刻重新比對，
  不用自己去 Explorer 找資料夾、也不用自己照規則打檔名。已比對成功的檔案是可點連結，
  點了直接開啟原始檔案（PDF/圖片就地預覽，Word/Excel 照瀏覽器慣例下載）——App 仍然
  不複製檔案進資料庫，這兩個動作都是即時讀寫磁碟上的真實檔案，符合「不搬移你的文件」
  的原始設計。

**週報** — 選任一天按「產生週報」，出四段式報告：
本週完成 → 未完成與原因 → **浮時消耗預警** → 下週關鍵路徑，另加里程碑、文件關卡與決策事項。
第一行永遠是「較原訂承諾早/晚幾天」，不是浮時或完成率。三種輸出：
- **📧 下載給主管的 HTML** — 單一自足檔案，不用開這個系統、雙擊即可看、可直接列印成 PDF，適合當附件寄出
- **📊 Excel 對照表** — 免裝套件，Excel 原生可開，開了之後排序／篩選都是 Excel 本身的功能
- **.md** — 你自己複製貼上用的操作紀錄

**設定** — `docs_root`、工作時段、國定假日。
**假日一定要填**，不填浮時會少算（把週六日以外的連假當成工作日）。

## 六、文件目錄與命名規則

在「階段與文件」頁按 **建立目錄骨架**，會在 `docs_root` 下產生：

```
<docs_root>/
└─ P01_示範專案一/
   ├─ 00_專案總覽/          （內含「檔名規則.txt」，全部代碼一覽）
   ├─ 01_S01_需求規劃/
   ├─ 02_S02_立案簽呈/
   ├─ 03_S03_POC 驗證/
   ├─ …
   └─ 99_往來信件與會議紀錄/
```

檔名規則：

```
{專案代號}_{階段序}_{文件代碼}_{說明}_v{版次}_{YYYYMMDD}.{副檔名}
例：P01_02_PROPOSAL_立案簽呈_v1_20260901.docx
```

**關鍵只有「文件代碼」那一段**，其餘欄位隨你高興。掃描時比對的就是這個代碼。
檔名沒有代碼的檔案不會消失，會列在該階段的「未能對應」清單裡。

**這條規則只有「手動存檔到資料夾」才需要自己遵守**——如果是用「階段與文件」頁每個
應繳項目旁的「📤 上傳」按鈕，檔名整段都是系統自動照這條規則產生，不會打錯。

真的有文件但掃不到（放在別的系統、紙本、簽核系統裡），
勾「手動標記已備妥」即可，關卡一樣會過。

## 七、階段與應繳文件

| 階段 | 出場關卡 | 必繳 |
|---|---|---|
| S01 需求規劃 | 需求規格與效益評估經主管確認 | REQ-SPEC、FEAS |
| S02 立案簽呈 | 簽呈完成核決，預算到位 | PROPOSAL、BUDGET、APPROVAL |
| S03 POC 驗證 | 驗證報告結論明確 | POC-APPLY、POC-PLAN、RFP、POC-RPT |
| S04 招標與議價 | 決標簽呈核決 | RFP-FINAL、VENDOR-CMP、QUOTE、AWARD |
| S05 合約簽呈 | 雙方用印完成 | CONTRACT-PRE、CONTRACT-DRAFT、LEGAL、CONTRACT-SIGN |
| S06 建置與導入 | 環境完成並通過基本檢核 | ARCH、ENV-BUILD、MIG-PLAN |
| S07 測試與驗證 | UAT 通過、無高風險未處理 | TEST-PLAN、TEST-CASE、UAT、SEC-SCAN |
| S08 上線切換 | 切換完成、回復方案未啟用 | CUTOVER、ROLLBACK、GO-LIVE |
| S09 驗收與結案 | 驗收核決、維運交接完成 | ACCEPT、TRAINING、OPS-HANDOVER、CLOSE |

要改階段或文件清單，編輯 `app/templates/stage_template.json`，
然後對專案呼叫 `POST /api/projects/<id>/apply-template`（帶 `{"overwrite":true}` 會重建）。

## 八、匯出 Google 日曆

「專案 WBS」頁右上 **匯出 .ics** → Google 日曆 → 設定 → 匯入。
匯出內容：未完成任務的區間、關鍵任務的「最後可動工日」提醒（前一天跳通知）、
每日雙專案工作 block、每日 17:20 收尾檢核、週四追補時段、週五 14:00 週報。

已完成的任務不匯出——日曆不是歷史檔案庫。

> 建議在 Google 日曆先建一個獨立日曆再匯入，之後要重匯只需清空那個日曆。

## 九、初始資料的說明

`app/seed.py` 裡的兩個專案是**通用示範資料**（假的專案名稱、假的人名），只在第一次
啟動、資料庫還沒有任何專案時才會種進去，方便你一開機就有東西可以操作、示範怎麼用。
真實的專案資料請直接在系統裡輸入，不要寫進 `seed.py`——這支檔案會隨程式碼一起流通。

要重來一次：刪掉 `data/wbs.db` 再啟動即可。

## 十、每天／每週怎麼用

| 時機 | 動作 | 花多久 |
|---|---|---|
| 每天早上 | 開「今日」頁，看紅燈項目 | 1 分鐘 |
| 每天 17:20 | 在「今日」頁更新進度按記錄 | 5 分鐘 |
| 收到／產出文件時 | 照命名規則存進對應階段資料夾 | 0 分鐘（存檔時順手） |
| 每週四下午 | 追補落後項，不排新工作 | — |
| 每週五 14:00 | 按「產生週報」，檢查後複製 | 10 分鐘 |

第二列是整套系統的成敗關鍵。沒有每日 5 分鐘，週五就只能靠回憶——那就跟現在沒兩樣。
